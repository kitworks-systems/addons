Multi-layer signup form protection for Odoo. This module provides four
independent protection mechanisms that can be enabled or disabled individually
through Settings:

1. **Honeypot** -- a hidden form field that catches automated bots
2. **Google reCAPTCHA v3** -- invisible CAPTCHA verification
3. **Disposable email blocking** -- prevents registration with throwaway email addresses
4. **Email verification** -- requires email confirmation before user account creation

By default, only the honeypot protection is enabled after installation.

Configuration
=============

All protection layers are configured in **Settings > Signup Protection**.
Each layer has an independent toggle and can be used in any combination.

Honeypot
--------

Enabled by default. No additional configuration required.

A hidden field named ``website_url`` is added to the signup form. The field is
invisible to human users (hidden via CSS) but is typically filled in by
automated bots. When the field contains a value, the signup is rejected.

Google reCAPTCHA v3
-------------------

Disabled by default. Requires Google reCAPTCHA keys to be configured first.

1. Go to **Settings > General Settings > Integrations** and configure your
   Google reCAPTCHA v3 site key and secret key.
2. Go to **Settings > Signup Protection** and enable
   *Enable reCAPTCHA on Signup*.

The module uses Odoo's built-in ``google_recaptcha`` integration. The reCAPTCHA
token is obtained automatically via JavaScript before form submission and
verified server-side using the ``ir.http._verify_request_recaptcha_token()``
method.

Disposable Email Blocking
--------------------------

Disabled by default.

1. Go to **Settings > Signup Protection** and enable
   *Block Disposable Email Domains*.

The module ships with a pre-loaded list of 90+ known disposable email domains
(mailinator.com, guerrillamail.com, yopmail.com, tempmail.com, etc.).

To manage the domain list:

- Go to **Settings > Technical > Disposable Email Domains**
- Add new domains, archive or delete existing ones
- Archived domains are excluded from blocking

When a user attempts to sign up with an email address from a blocked domain,
the registration is rejected with a clear error message.

Email Verification
------------------

Disabled by default.

1. Go to **Settings > Signup Protection** and enable
   *Enable Email Verification on Signup*.
2. Optionally adjust the *Verification Token Expiration* (default: 24 hours).

When enabled, the signup flow changes:

1. User fills in the signup form and submits it.
2. Instead of creating a user account immediately, a pending signup record is
   created and a verification email is sent.
3. The user clicks the verification link in the email.
4. The user account is created and the user is logged in automatically.

Rate limiting is enforced to prevent abuse:

- Maximum 3 signup attempts per email address per hour
- Maximum 5 signup attempts per IP address per hour

A scheduled action (**Cleanup Expired Pending Signups**) runs daily to:

- Mark expired pending signups (past expiration date)
- Delete expired and verified records older than 7 days

Pending signups can be monitored at **Settings > Technical > Pending Signups**.

Usage
=====

Once installed and configured, the module works transparently. The signup form
at ``/web/signup`` is automatically enhanced with the enabled protection layers.

No changes to the standard signup URL or workflow are required. Users interact
with the same ``/web/signup`` page. The protections are applied server-side
(and client-side for reCAPTCHA) during form submission.

Verification Endpoint
---------------------

When email verification is enabled, a new route is available:

- ``/web/signup/verify?token=<token>`` -- verifies the email and creates the
  user account.

Models
======

kw.pending.signup
-----------------

Stores pending signup requests when email verification is enabled.

Fields:

- ``login`` (Char) -- email address used for signup
- ``name`` (Char) -- user display name
- ``password`` (Char) -- temporarily stored password (cleared after verification)
- ``signup_values`` (Text) -- JSON-encoded extra signup values
- ``lang`` (Char) -- user language code
- ``token`` (Char) -- 20-character random verification token
- ``expiration`` (Datetime) -- token expiration timestamp
- ``state`` (Selection) -- pending / verified / expired
- ``ip_address`` (Char) -- IP address of the signup request
- ``last_sent`` (Datetime) -- timestamp of the last verification email

kw.disposable.email.domain
---------------------------

Stores known disposable email domains.

Fields:

- ``name`` (Char) -- domain name (e.g., ``mailinator.com``)
- ``active`` (Boolean) -- whether the domain is actively blocked

Known issues / Roadmap
======================

- The disposable email domain list is static and loaded on installation.
  Consider periodically updating it from external sources.
- reCAPTCHA v3 requires proper DNS and HTTPS configuration to function
  correctly.
